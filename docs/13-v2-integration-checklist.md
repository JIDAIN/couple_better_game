# V2-P11 全站联调与收尾检查

## 1. 当前边界

生活系统主导航固定为：

```text
今日 / 饮食 / 日历 / 小窝 / 我的
```

旧「变美变瘦大作战」不是生活层主导航的一部分，只允许从：

```text
小窝 -> 游戏机 -> 变美变瘦大作战 -> /game
```

进入。

`/game` 继续挂载原有 `HomeScreen`。金币、宝石、兑换、钱包、结算、奖励与原规则保持独立。

## 2. 饮食边界

新版详细餐食只属于 `/food`：

- 早餐 / 午餐 / 晚餐 / 加餐；
- 餐食照片与默认卡通图；
- 食物明细；
- 宏量营养和 kcal；
- Meal CRUD / AI 写入。

旧游戏不再展示或编辑详细餐食。`DailyMealsPanel` 在旧游戏侧仅保留为空兼容层，避免把新版餐食 UI 重新带回 `/game`。

## 3. 数据边界

- 生活事实：通过 Next.js API 读写 Supabase；
- 浏览器不持有 Supabase server secret；
- 体重仍以 `weight_measurements` 为事实源；
- 药箱、信箱、日历、饮食使用各自领域 API；
- 旧游戏奖励结算不依赖新版详细餐食记录。

## 4. 自动回归检查

`tests/life/v2-integration-boundaries.test.ts` 固定检查：

1. 游戏机唯一当前可玩项目仍路由到 `/game`；
2. 「我的」不提供绕过游戏机直接进入 `/game` 的快捷入口；
3. `/game` 仍由旧 `HomeScreen` 提供；
4. 旧游戏餐食适配层不重新接回详细 Meal UI；
5. `/food` 保持生活层独立路由；
6. `vercel.json` 继续关闭 Git 自动部署。

## 5. Preview 前人工验收清单

只有得到明确「允许部署」后才创建 Vercel Preview。Preview 出来后，优先用手机尺寸逐项检查：

- 底部导航是否遮挡最后一张卡片或按钮；
- 今日的心情、睡眠、活动新增/编辑/错误状态；
- 饮食我/Ta 切换、四餐空状态、默认卡通图、上传图片、编辑一餐；
- 日历月份切换、双人心情标记、日期详情；
- 小窝四入口及子页返回逻辑；
- 体重趋势在窄屏下是否溢出；
- 药箱长药名、筛选、日期状态、数量编辑；
- 小信箱长正文、收到/寄出切换、编辑和删除；
- 游戏机 -> 变美变瘦大作战 -> `/game`；
- `/game` 中确认没有详细早餐/午餐/晚餐/加餐面板；
- 旧游戏金币、宝石、兑换、结算与同步流程回归；
- 「我的」不出现直接 `/game` 入口。

## 6. 发布约束

仓库维持：

```json
{
  "git": {
    "deploymentEnabled": false
  }
}
```

任何 Preview 或 Production 部署都必须逐次取得用户明确批准。
