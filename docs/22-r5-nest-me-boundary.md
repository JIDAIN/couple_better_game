# R5：小窝 / 我的职责重分

> 状态：✅ 2026-09-03 完成。

## 1. 页面职责

最终边界：

```text
小窝 = 两个人共同拥有 / 使用的生活内容
       体重 / 小信箱 / 家庭药箱 / 游戏机

我的 = 当前登录账号与应用边界
       身份 / 云同步 / 写入权限 / 数据管理 / 退出登录
```

“我的”不再重复介绍小窝、日历和产品理念；“小窝”也不承担账号设置。

## 2. 小窝

仍保持既定 2×2 四入口，不新增功能：

- 体重；
- 小信箱；
- 家庭药箱；
- 游戏机。

顶部改为生活房间场景，四个入口仍是明确可点击的共享对象。

## 3. 我的

“我的”直接消费根 `LifeIdentityContext`，不再自己重复请求 session。

展示：

- 当前稳定账号：猫猫（cat）/鱼鱼（fish）；
- 当前相对身份：我 = mePartnerKey，Ta = taPartnerKey；
- 云端事实源与缓存边界；
- 个人写入权限说明；
- 旧游戏数据管理仍在旧游戏内，不在生活系统复制一套；
- 退出当前账号。

## 4. 小信箱权限

UI 规则：

- 新写信固定 `我 -> Ta`，不提供寄件人切换；
- 收到的信只读；
- 自己寄出的信可以编辑/删除；
- 切换登录账号后“收到 / 寄出”自动反转到新的“我”。

服务端同时加固：

- POST：senderKey 必须等于当前 session.partnerKey；
- PUT/DELETE：先从数据库读取已有信件 sender，再确认当前账号就是原寄件人；
- PUT 不允许把寄件人改成 Ta，也不允许寄给自己。

因此不能只靠篡改前端 payload 冒充另一方寄信或改信。

## 5. 验收

- 小窝只保留共同生活四入口；
- 我的不再出现重复的小窝/日历快捷入口堆叠；
- 我的能明确看到当前账号、同步边界和退出；
- 新信固定由当前账号寄给 Ta；
- 收到的信无编辑/删除按钮；
- API 也拒绝修改 Ta 寄出的信。
