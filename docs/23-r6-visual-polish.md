# R6：全站视觉还原

> 状态：✅ 2026-09-03 完成代码与文档阶段，等待统一 Test / Lint / Build 验收。

## 1. 目标

R6 不再改业务信息架构，而是把 R1-R5 已稳定的结构统一拉回已确认的“岛屿生活 V2 · 方案 B”。重点解决 Production 首轮验收中“只是圆角 SaaS 卡片、与视觉模型差距大”的问题。

## 2. 统一视觉层

保留 `app/island-life-tokens.css` 作为 token 源；新增并统一使用：

```text
app/island-life-refactor.css
```

它是页面级 visual adapter，不承载业务数据逻辑。

统一内容：

- 暖白 / 奶油背景，薄荷和柔黄环境色；
- 页面标题更轻、更像生活应用；
- 底部导航改为半透明暖白材质与薄荷激活态；
- 普通 surface 降低后台 Dashboard 感；
- 数据密集页仍保持规整，不牺牲可读性。

## 3. 关键页面

### 今日
心情使用独立 bottom sheet、柔和不规则情绪色块；不再把七个按钮硬塞进卡片正文。

### 饮食
结构仍以数据为主，不额外堆主题插画。通过统一 surface、role switch、sheet、间距和色彩融入系统。

### 日历
重做为纸质感稀疏月历：日期本身是主结构，情绪图像自然散落在日期下，不再每格一个 SaaS 卡片。

### 小窝
顶部从说明卡片改为房间场景：窗、阳光、绿植、沙发和两位稳定账号的猫/鱼符号；下面仍保持清楚的 2×2 四入口。

这里的猫/鱼只是项目稳定账号图形符号，不是 Nintendo 官方人物资产。用户后续提供自己的实际游戏角色参考后，可单独替换人物层，不改变布局结构。

### 我的
改为账号 Hero + 设置列表：身份、云同步、写入权限、数据管理、退出。共同生活入口不再重复出现。

## 4. 第三方复用原则

本轮继续遵守：

```text
成熟逻辑 / Pattern 可以借
第三方视觉体系不能直接污染业务页
专有角色 / 官方 Nintendo 素材不复制
```

日历参考 MIT `GitHub-Xzhi/obsidian-mood-calendar` 的 mood-under-date 产品模式；基础 UI 继续使用既有 `animal-island-ui` / App* 分层。

## 5. Legacy Game 边界

R6 没有重做 `/game`：

- 旧游戏奖励、金币、宝石、兑换、钱包、结算不变；
- 新版 Meal 明细仍不回流旧游戏；
- `/game` 仍由游戏机进入。

## 6. 验收基线

- 主导航五项一致；
- 当前 Tab 不重新导航；
- 页面标题、导航、sheet、surface 使用同一视觉语言；
- 小窝明显是共享生活场景，不像“我的”；
- 我的明显是账户/设置页，不像小窝；
- 日历无心情时留白；
- 数据密集页不因为主题化降低扫读性；
- 不引入任何排名、streak 或双方评价。
