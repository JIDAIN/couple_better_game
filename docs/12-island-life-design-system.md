# 岛屿生活 Design System

这份文档是 V2 后续所有可见 UI 的**唯一主视觉规范**。任何首页、饮食、日历、小窝、体重、小信箱、家庭药箱、游戏机和未来新增页面，都必须先遵守本文件，再进入开发。

## 1. 核心目标

```text
统一 > 花哨
可读 > 主题化
成熟交互优先 > 重复造轮子
岛屿感来自整体语言 > 来自某一个组件库
```

`animal-island-ui` 是组件来源之一，不是整个视觉语言本身。组件不足时允许重新设计，但新组件必须使用项目统一 token / App* / Pattern，不能在业务页面形成第二套视觉系统。

## 2. 已确认的 V2 视觉方向

人工确认版本：**岛屿生活 V2 · 方案 B**。

### 色彩

主画面采用：

- 暖白 / 奶油白：页面主背景和大面积留白；
- 薄荷绿 / 青绿：主识别色、选中态和主要轻操作；
- 柔黄：重要但非危险的强调；
- 珊瑚：温暖、陪伴、少量强调；
- 浅蓝：睡眠、信息和安静状态；
- 深灰绿：正文和高可读文字。

**禁止重新回到大面积棕色、木板棕背景或全页面黄褐色。** 木质/纸张只能作为少量物件语义和插画点缀。

当前代码 token 源：

```text
app/island-life-tokens.css
```

V2 使用 `--life-*` token，与 Legacy Game 旧视觉变量并存，不强迫 `/game` 一起改版。

### 形状与层级

- 卡片圆角柔和，但不把所有信息都做成大胶囊；
- 主卡片约 22px 圆角，控件约 16px，小元素约 12px；
- 阴影轻、散、低对比，不使用企业 Dashboard 的重阴影；
- 按压/选中可以有轻微立体感，但不能影响控件识别；
- 高信息密度区域优先靠留白、分组、对齐建立层级。

### 图标与插画

- 图标采用圆润、低饱和、生活物件感；
- 首页和小窝允许更多自然元素与轻插画；
- 图表、营养、药品列表等数据密集区域减少装饰；
- 不以 Nintendo 官方资产作为长期产品资源；
- 当前活动人物只作为临时女性岛民风占位，后续用户会提供双方实际动森角色图片/视频作为替换参考。

## 3. 主题浓度

```text
信息密度低 -> 主题更明显
信息密度高 -> 主题退到容器/色彩/层级
```

例如：

- 首页心情、活动、小窝：允许明显岛屿生活感；
- 饮食营养条：保持清楚，不用大量装饰；
- 体重折线图：图表内部干净；
- 药箱：药名、数量、保质期优先可扫读；
- 日历：保留标准七列日历结构，只主题化日期格和双人心情标记。

## 4. 70 / 20 / 10 检查法

这是设计检查法，不是硬比例：

- ~70% 熟悉、稳定、无需学习的 UI 行为；
- ~20% 岛屿色板、圆角、材质、容器和排版；
- ~10% 角色化、物件化、轻插画和微动画。

主题化后如果需要判断“这个东西是不是按钮”，就是过度设计。

## 5. 主信息架构（定稿）

```text
今日 / 饮食 / 日历 / 小窝 / 我的
```

### 今日

只显示：

```text
心情
睡眠
活动
```

三项都必须有明确记录/编辑入口。

- 心情：保留彩色情绪圆脸，不用人物头像代替；
- 睡眠：只记录入睡 / 起床，不评分；
- 活动：学习/运动/散步/游玩统一为活动。

### 饮食

- 顶部统一 `我 / Ta` 切换；
- 一次只看一人，不做双列对照；
- 早餐 / 午餐 / 晚餐 / 加餐；
- 每餐左侧是真实餐食照片；
- 每餐右侧是碳水 / 蛋白质 / 脂肪 / 总热量；
- 每餐有编辑按钮；
- 底部显示当日宏量营养和总热量统计；
- 不要饭历、印章墙、连续打卡奖励等视觉。

编辑按钮进入「编辑一餐」子页面，新增/编辑复用同一数据逻辑。

### 日历

- 保持已确认的双人心情月历；
- 同一天可以显示两人的情绪圆脸；
- 点击日期进入「日历详情」；
- 日历详情展示当日心情 / 睡眠 / 活动 / 饮食概览；
- 不引入成功率、连续打卡或生活绩效。

### 小窝

固定四个主要入口：

```text
体重
小信箱
家庭药箱
游戏机
```

#### 体重
- 顶部 `我 / Ta`；
- 当前体重；
- 周/月/年趋势；
- 折线图；
- 最近记录；
- 新增记录入口。

#### 小信箱
- 收到的 / 我写的；
- 信纸/便签式列表；
- 不使用人物头像做列表主体；
- 不统计谁写得更多，不做 streak。

#### 家庭药箱
- 搜索；
- 分类/状态筛选；
- 药名 / 规格 / 数量 / 保质期 / 存放位置；
- 添加/编辑药品；
- 信息密度高，因此主题化要克制。

#### 游戏机
游戏机只负责**游戏列表**。

当前：

```text
宝石金币游戏 -> 现有 Legacy Game
更多游戏 -> 敬请期待
```

本轮不开发新的「宝石金币游戏详情页」。未来新增游戏通过可扩展 registry 接入。

## 6. 双人切换规则

需要查看单人事实的页面统一使用：

```text
我 / Ta
```

不使用：

```text
我 / 她
我 / 对方
鱼 / 猫
```

已实现共享 Pattern：

```text
AppRoleSwitch
```

适用：饮食、体重，以及未来需要单人筛选的事实页。

## 7. UI 获取优先级

```text
A. 已有 App* wrapper
B. animal-island-ui 已验证能力
C. 同视觉语言、许可允许的成熟 GitHub Pattern
D. 成熟 headless / 通用组件库，仅借交互
E. 项目原创组件
```

从 0 写是最后选择。

外部代码：

1. 同风格组件：可复用结构/交互/部分视觉，再归一；
2. 异风格组件：只借逻辑/状态/布局；
3. 授权不明确：只做参考，不复制。

## 8. 当前重点参考仓库

- `guokaigdg/animal-island-ui`：基础组件、设计词汇；
- `TIUCSIB/animal-island-blog`：Timeline / Empty / Popover / Toast 等应用级 Pattern；
- `AshleyCry/AnimalIslandNewTab`：设置/侧栏/页面组合；
- `guowenju/portal-os`：小窝式 App Grid / 工具入口；
- `CheapNightbot/our-days`：情绪月历逻辑。

这些项目都不能把自己的视觉系统直接带入业务层。

## 9. 项目组件分层

```text
第三方基础 / headless
        ↓
components/ui/App*
        ↓
跨域 Pattern
        ↓
业务域组件
```

V2-UI1 已实现：

```text
AppPageShell
AppRoleSwitch
AppRecordRow
AppFeatureTile
AppNutritionBar
```

视觉 token：

```text
app/island-life-tokens.css
```

实验回归页：

```text
/ui-lab
```

`/ui-lab` 只能使用假数据。

## 10. `/ui-lab` 用途

用于同时检查：

- 定稿色板；
- 我 / Ta 切换；
- 心情；
- 睡眠；
- 活动；
- 饮食营养条；
- 小窝入口；
- 未来日历/药箱/体重 Pattern。

规则：

- 不读写 Supabase；
- 不调用真实 Life API；
- 不参与 Legacy Game settlement；
- 新 Pattern 先在这里统一，再进入业务页面。

## 11. 不允许的做法

- 重新大面积使用棕色/木板色；
- 每个页面单独发明色板；
- 把异风格 GitHub CSS 整包复制；
- 为了主题破坏标准日历/表单/图表交互；
- 用头像替代首页心情圆脸；
- 在饮食页面同时展示“我”和“Ta”的对照列；
- 在首页加入饮食、体重、药箱、小信箱；
- 游戏机本轮擅自增加 Legacy Game 新详情 UI；
- 在生活系统使用金币、经验、排名、streak 等旧游戏评价语义；
- 把实验 UI 当成 production 已上线。

## 12. 开发强制流程

任何可见 V2 UI 开发前：

1. 阅读本文件；
2. 检查是否已有 App* / Pattern；
3. 如参考 GitHub，确认许可证和复用层级；
4. 使用 `--life-*` token；
5. 新跨域组件优先进入 `components/ui`；
6. 先在 `/ui-lab` 检查统一性；
7. Test / Lint / Build；
8. Vercel Preview 人工检查；
9. 通过后进入业务页面。

大型视觉方向变化必须先修改本文件并重新人工确认，不能在单个业务 PR 中顺手改变。
