# 岛屿生活视觉语言 V2（定稿）

> **状态：已人工确认，作为 V2 后续可见 UI 的唯一主视觉规范。**
>
> 后续首页、饮食、日历、小窝、体重、小信箱、家庭药箱、游戏机及新增功能，必须先遵守本文件；如果现有组件无法满足，可以新增/改造组件，但不能另起一套视觉体系。

## 1. 产品气质

V2 不是“把所有控件都做成动森按钮”，而是建立统一的「岛屿生活」视觉语言：

```text
温柔治愈
轻松陪伴
信息清楚
生活感强
可爱但不过度幼稚
有动森气息但不复刻 Nintendo 官方 UI
```

核心判断：

```text
统一 > 花哨
可读 > 主题化
成熟交互优先 > 重复造轮子
岛屿感来自整体空间与细节 > 来自某一个组件库
```

`animal-island-ui` 是组件来源之一，不是整个 Design System 本身。

## 2. 已确认的视觉方向

最终方向以人工确认的「方案 B」为准：

- 背景以**暖白 / 奶油白**为主，不使用大面积棕色；
- 页面整体比纯薄荷绿版本更温馨，但仍保持清爽；
- 主识别色为**薄荷绿 / 青绿**；
- 辅助使用**柔和黄色、珊瑚粉、浅蓝**；
- 深色只用于正文、标题和必要轮廓；
- 自然元素以小岛、树叶、花朵、海水、草地、家居小物等形式点缀；
- 卡片留白充足，圆角柔和，阴影轻；
- 数据密集页面降低插画占比，保证数字与列表易读。

### 建议基础色 Token

以下作为实现起点，后续若微调必须在全局 token 层完成，不允许页面自行创造新色板：

```text
--island-bg:             #FFF4E6   暖白背景
--island-surface:        #FFFAF2   卡片/内容表面
--island-cream:          #FFECC2   奶油辅助
--island-warm-yellow:    #FFD8A8   暖黄
--island-coral:          #FF9E8E   珊瑚粉
--island-mint:           #AEDCC8   薄荷绿
--island-aqua:           #CFEFEA   淡青
--island-green:          #8FC6A1   主绿色
--island-green-deep:     #5E8E75   深绿色
--island-text:           #4F4B45   主文字
--island-text-muted:     #8A8379   辅助文字
```

原则：**暖感主要来自暖白、奶油、黄和珊瑚色，不靠大面积木棕。**

## 3. 字体与层级

字体气质：圆润、友好、清楚，不追求强手写感。

```text
Page title       22–28 / Semibold
Section title    17–20 / Medium-Semibold
Body             14–16 / Regular
Caption          11–13 / Regular
Numeric metric   16–28 / Semibold，启用 tabular nums
```

要求：

- 中文正文优先可读性；
- 不用纯装饰字体承载大量数字或药品名称；
- 页面标题可以有轻微动森感，数据内容保持稳重。

## 4. 形状、圆角、阴影与材质

### 圆角

```text
小控件      12–14px
普通卡片    18–22px
大容器      24–28px
胶囊按钮    999px
```

### 阴影

- 默认使用轻阴影；
- 不做重玻璃拟态；
- 不使用企业后台式强边框 + 强阴影；
- 可点击卡片允许很轻的浮起/按压反馈。

### 材质

允许：

- 纸张、便签、信纸；
- 柔和草地/海岛插画；
- 家居、药箱、信箱、游戏机等生活物件语义。

避免：

- 大面积木纹；
- 高密度树叶铺满背景；
- 数据表格上叠大量装饰；
- 为了“像动森”牺牲按钮、输入框、日期等熟悉交互。

## 5. 图标与插画

### 图标

统一为：

```text
圆润线条 + 少量柔和填色 + 自然/生活物件语义
```

核心图标语义：

- 今日：叶片 / 小芽；
- 饮食：餐具 / 食物；
- 日历：日历；
- 小窝：小屋；
- 体重：体重秤；
- 小信箱：信封；
- 家庭药箱：医药箱；
- 游戏机：掌机；
- 心情：彩色圆形情绪脸；
- 睡眠：月亮；
- 活动：鞋/叶片等生活活动符号。

### 双人形象

- 用户与伴侣均使用女性角色形象；
- 首页活动插画当前只允许使用临时的动森风女性角色；
- 用户后续提供双方真实动森角色图片/视频后，统一替换临时人物；
- 在正式角色资产到位前，不再使用“男孩 + 女孩”组合；
- 心情区域**不使用人物头像**，继续使用已确认的彩色情绪圆脸。

## 6. 主题浓度

```text
信息密度低 -> 主题可以更明显
信息密度高 -> 主题退到容器、插画和状态色，数据本身保持克制
```

例子：

- 首页：主题感最强；
- 小窝：通过家居/物件入口制造空间感；
- 日历：保留标准七列结构，只做情绪标记和背景；
- 饮食：实物照片 + 营养数字优先，主题退到卡片和按钮；
- 体重：图表必须清楚，插画只在顶部或空状态点缀；
- 药箱：药名、数量、到期日优先，插画只用于图标和状态。

## 7. 主导航与页面结构（定稿）

主导航：

```text
今日 / 饮食 / 日历 / 小窝 / 我的
```

V2 正式页面不得沿用旧游戏的 `今日 / 地图 / 兑换 / 小窝` 作为生活系统主导航；旧游戏继续在「小窝 -> 游戏机」中进入。

## 8. 主页面规格

### 8.1 今日页

今日页只保留三个高频生活事实：

```text
心情
睡眠
活动
```

三块区域都必须有明确的 `+ 记录` / 编辑入口。

#### 心情

- 使用已确认的彩色情绪圆脸；
- 双方并列展示当前心情；
- 不使用人物头像替代心情图标；
- 点击 `+ 记录` 后选择情绪；
- 不做分数、排名、连续打卡奖励。

#### 睡眠

- 显示双方睡眠时长；
- `+ 记录` 进入简单入睡 / 起床时间录入；
- 不做睡眠评分。

#### 活动

- 显示当天共同/个人活动摘要；
- `+ 记录` 允许追加活动；
- 页面只叫“活动”，不拆成学习 / 运动 / 散步多个固定任务；
- 临时人物只使用女性动森风角色，后续替换为用户提供的双方角色。

首页不出现：饮食、体重、药箱、小信箱、旧游戏资源。

### 8.2 饮食页

饮食页是从旧游戏中独立出来的**每日饮食事实页**，不是比较页。

顶部角色切换固定为：

```text
我 / Ta
```

禁止使用：

```text
我 / 她
我 / 对方
我和Ta同时并列对照
```

默认只展示当前选择者的一天饮食。

#### 每餐结构

按顺序：

```text
早餐
午餐
晚餐
加餐
```

每餐一行/一卡：

```text
左侧：当天真实餐食照片
右侧：本餐营养统计
      - 碳水化合物
      - 蛋白质
      - 脂肪
      - 总热量
右上：编辑按钮
```

没有照片时使用轻量占位，不固定展示某个食物插画。

底部显示：

```text
今日营养摄入总览
碳水 / 蛋白质 / 脂肪 / 总热量
```

可以用柔和进度条/色条帮助判断营养结构，但不能把饮食变成竞技得分。

不要做：

- 本周饭历；
- 印章墙；
- 吃饭打卡收集；
- 我和 Ta 的同屏摄入对照；
- 固定食物插画替代真实餐食照片。

### 8.3 日历页

主日历保持已确认的版本：

- 标准月历七列；
- 每天显示双方心情小圆脸；
- 颜色柔和、信息紧凑；
- 点击某天进入「日历详情」；
- 不增加成绩/连续打卡语义。

### 8.4 小窝页

小窝保持已确认的“家居空间 + 四个功能物件卡”版本：

```text
体重
小信箱
家庭药箱
游戏机
```

四块入口采用统一尺寸和物件插画；小窝是低频功能集合，不把这些内容重新塞回首页。

## 9. 子页面规格

### 9.1 编辑一餐

从饮食页每餐右上编辑按钮进入；新增餐食也复用同一页面。

页面结构：

```text
早餐 / 午餐 / 晚餐 / 加餐切换
餐食图片（可替换）
食物清单
  - 食物名
  - 份量
  - kcal（允许未来为可选）
时间
地点（可选）
备注（可选）
本餐营养小结
  - 总热量
  - 蛋白质
  - 脂肪
  - 碳水
保存
```

不在该页面引入金币/宝石/deficit。

### 9.2 日历详情

点击日历中的某一天进入。

按生活事实展示：

```text
当日心情
当日睡眠
当日活动
当日饮食概览
```

只回顾当天发生的事情，不评分。

### 9.3 体重页

顶部角色切换与饮食一致：

```text
我 / Ta
```

只展示当前选择者，不做双线竞技对照。

页面包含：

```text
当前体重
与上次差值（描述性）
周 / 月 / 年趋势切换
折线图
近期记录
+ 记录体重
```

体重图表内部保持克制，岛屿插画只用于外层或点缀。

### 9.4 小信箱

禁止使用人物头像作为消息列表主体。

结构：

```text
收到的 / 我写的
信纸卡片列表
日期
正文摘要
```

视觉使用信纸、邮票、花叶等轻装饰；不做谁写得多、连续写信等计数。

### 9.5 家庭药箱

页面结构：

```text
搜索
全部 / 即将过期 / 常备等轻筛选
药品列表
  - 药名
  - 规格
  - 数量
  - 有效期
  - 存放位置
+ 添加药品
```

药品条目以可扫描信息为主，不做复杂游戏卡牌。

#### 添加/编辑药品

```text
药品名称
规格
数量 / 单位
有效期
存放位置
备注（可选）
保存
```

未来 Excel 导入和 AI 修改复用同一 canonical medicine domain，不另造数据结构。

### 9.6 游戏机

游戏机只做**游戏列表 / 游戏入口**，本阶段不设计游戏详情页。

当前：

```text
宝石金币游戏
```

即旧版“通过饮食/原有规则获得金币宝石，再兑换奖励”的完整游戏机制。

未来：

```text
更多游戏（占位）
```

架构要求：

- 游戏列表必须可扩展；
- 每个游戏有稳定 `gameKey / title / cover / status / route`；
- 新游戏不得迫使生活记录主数据变成排行榜数据；
- 旧版宝石金币游戏继续使用现有 `components/home` / `lib/home` 机制；
- **V2 UI 当前只做到游戏列表，游戏详情页不进入本轮视觉开发。**

## 10. UI 获取与复用优先级

新增可见 UI 时按以下顺序：

```text
A. 已有 App* wrapper
B. animal-island-ui 已确认可用组件
C. 同视觉语言、许可允许的成熟 GitHub Pattern
D. 成熟 headless / 通用库的交互能力
E. 项目原创组件
```

从 0 写不是默认方案。

当前主要参考：

```text
guokaigdg/animal-island-ui
TIUCSIB/animal-island-blog
AshleyCry/AnimalIslandNewTab
guowenju/portal-os
CheapNightbot/our-days
```

### 外部代码适配规则

允许复用：

- 状态管理；
- 日期算法；
- 键盘 / accessibility；
- 列表、Timeline、Popover、Toast、Drawer 等成熟交互；
- 响应式布局思路。

不允许直接带入：

- 外部项目独立色板；
- 外部项目自己的 Button / Card / Modal 视觉；
- 大片第三方 CSS；
- 与本视觉语言冲突的阴影、圆角、字体。

外部 UI 必须先经过 `components/ui/App*` 或项目 Pattern 适配，再进入业务页面。

## 11. 组件分层

```text
基础库 / headless
        ↓
components/ui/App*
        ↓
跨域 Project Pattern
        ↓
components/life / nutrition / weight / medicine / games
```

建议长期 Pattern：

```text
AppPageShell
AppSectionPanel
AppRecordRow
AppEmptyState
AppPopover
AppToast
AppFeatureTile
AppMonthCalendar
AppRoleSwitch（我 / Ta）
```

## 12. 动效与反馈

- 按钮按压反馈短且柔和；
- 页面切换不做大幅弹跳；
- 保存成功可用小型 Toast；
- loading 使用 Skeleton/轻量 loading；
- 错误提示清楚，不使用“角色哭泣”等情绪化惩罚动画；
- 不用持续晃动/呼吸动画抢注意力。

## 13. 强制一致性规则

后续开发必须遵守：

1. **任何新增业务页面开始编码前，先对照本文件确认页面属于哪个视觉模式。**
2. **业务 JSX 不允许直接创造第二套颜色、圆角、阴影体系。**
3. 新增 token 必须先进入全局设计 token，再由组件消费。
4. 新增视觉 Pattern 优先在 `/ui-lab` 以假数据验证，再接生产 API。
5. 涉及主导航、主页面布局、色板或核心组件形态的变化，必须先更新本文件并重新人工确认。
6. 小改动不得顺手改变已确认页面的信息架构。
7. 生活系统不得使用旧游戏的金币、宝石、热力图、排名等视觉语义。
8. 高密度数据页面必须以可读性优先。
9. `我 / Ta` 是双人切换的统一文案。
10. 已确认的主页面/子页面结构不能由实现者自行删减或替换。

## 14. `/ui-lab`

`/ui-lab` 继续作为开发用视觉实验室，不是正式导航。

用途：

- 对比 App*；
- 试验新增 Pattern；
- 验证不同屏宽；
- 升级 `animal-island-ui` 时集中做视觉回归；
- 药箱、日历、体重等新增组件先在这里验证。

要求：

- 只使用假数据；
- 不读写 Supabase 生活事实；
- 不触发旧游戏 settlement；
- UI Lab 不是视觉规范本身，**本文件才是规范源**。

## 15. 不允许的做法

- 大面积棕色背景/标题重新成为主色；
- 把所有页面刷成同一种浅绿色；
- 首页把饮食、体重、药箱、信箱重新塞回来；
- 心情用人物头像替代情绪圆脸；
- 饮食页做双人同屏对照；
- 饮食页恢复饭历/印章墙；
- 小信箱使用人物头像列表；
- 体重页缺少 `我 / Ta` 切换；
- 游戏机直接展开旧游戏详情；
- 为了动森感改变标准日期、表单、图表心智模型；
- 复制 Nintendo 官方游戏资产作为长期核心资源；
- 从不同 GitHub 项目拼出多套色板和组件风格。

## 16. 视觉变更验收

代码检查：

```text
npm run test
npm run lint
npm run build
```

视觉检查至少包含：

- 常见手机宽度；
- 长中文；
- 空数据 / loading / error；
- 饮食有/无照片；
- 多个食物 item；
- 月历 28/29/30/31 天和跨月；
- 药品名、规格、到期日较长；
- 体重趋势数字对齐；
- 底部导航 safe-area；
- Modal / Drawer / 页面表单滚动。

未人工检查时，不得在文档中声称“视觉已验证”。
