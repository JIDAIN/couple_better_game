
# 页面交互说明文档：双人变美变瘦大作战

本文档说明项目中主要页面和组件的展示内容、按钮行为、弹窗逻辑、输入校验、状态反馈和移动端适配要求。

```text
HomeScreen
GameTitle

CoupleGrowthPanel
RecordTodaySettlement

GrowthLog
ExchangeShop
EncouragementQuote
HomeResourcesProvider
```

# 2. HomeScreen 首页

## 页面位置

应用首页主容器。

## 展示内容

首页当前包含：

```text
标题区
作战进度状态
成长资源面板
成长地图
鼓励小纸条
记录今天按钮
成长日志入口
兑换商店入口
```

这些内容在 `HomeScreen` 中按顺序组合：`GameTitle`、`CampaignProgressBadge`、`CoupleGrowthPanel`、`DualMonthlyHeatmaps`、`EncouragementQuote`、`RecordTodayButton`、`GrowthLog`、`ExchangeShop`。

## 用户操作

用户可以：

```text
查看当前作战状态
查看资源和成长地图
点击记录今天
点击成长日志
点击兑换商店
```

## 系统响应

* 点击 `记录今天` 打开记录弹窗；
* 点击 `成长日志` 打开成长日志弹窗；
* 点击 `兑换商店` 打开兑换商店弹窗；
* 首页状态会随每日记录、兑换记录、本地数据变化自动刷新。

## 移动端适配

首页主体使用窄屏居中容器，适合移动端纵向浏览。当前布局底部入口为两列：成长日志和兑换商店。

# 4. CampaignProgressBadge 作战进度

## 页面位置

首页标题下方。

## 展示内容

展示作战是否已开启，以及当前是第几天。

当前组件通过 `heatmapStartDate` 和当前日期计算作战天数。为避免 hydration mismatch，组件使用 `useSyncExternalStore` 区分服务端和客户端挂载状态，挂载前不直接渲染依赖 `new Date()` 的天数。

## 状态

### 未设置开始日

显示：

```text
设置作战开始日后，就能记录我们的第几天啦
```

### 尚未开始

显示：

```text
变美变瘦大作战即将开始
```

### 已开始

显示：

```text
变美变瘦大作战已开启
第 n 天 ✨
```

## 交互行为

无直接交互。

## 异常情况

如果开始日为空或无效，应显示温和提示，不应报错。

# 6. RecordTodaySettlement 记录今天弹窗

## 页面位置

首页主按钮 `记录今天`。

## 功能目标

用户记录某一天鱼鱼和猫猫的数据，并预览当日奖励。

## 入口

```text
首页 → 记录今天
```

组件支持 `today` 和 `history` 两种按钮变体，`buttonVariant === "history"` 时显示补录记录入口，否则显示记录今天入口。

---

## 打开逻辑

用户点击按钮后：

1. 系统获取当前日期；
2. 查找当天是否已有记录；
3. 如果已有记录，则带出原数据；
4. 如果没有记录，则使用默认输入值；
5. 打开弹窗。

---

## 弹窗展示内容

弹窗包括：

```text
标题区
记录日期输入
鱼鱼记录卡
猫猫记录卡
奖励预览
底部操作按钮
```

## 表单字段

每个人包含：

```text
今日体重
运动时长
热量缺口
```

当前输入组件使用 `CompactField`，字段名、输入框和单位位于同一行。`CompactField` 支持 `decimal`、`numeric`、`text` 输入模式，并在输入框右侧显示单位。

---

## 输入规则

### 体重

* 可为空；
* 空值解析为 `null`；
* 非正数视为无效或空值。

### 热量缺口

* 非负整数；
* 空值或非法值按 0 处理。

### 运动时长

* 非负整数；
* 空值或非法值按 0 处理。

输入解析依赖 `parseOptionalWeight` 和 `parseNonNegativeInt`。

---

## 奖励预览

用户输入后，系统实时计算：

```text
鱼鱼宝石
猫猫宝石
情侣 bonus
金币变化
```

系统会根据当前记录日期，查找前一天记录，用于计算恢复奖励。

---

## 保存逻辑

用户点击保存后：

1. 校验是否有有效输入；
2. 校验日期是否合法；
3. 调用 `upsertDailyRecord` 保存或更新记录；
4. 成功后关闭弹窗；
5. 显示 toast。

## toast 提示

保存成功时：

```text
今天已经存好啦，明天继续并肩
这一天已经更新完成
这一天已经补录完成
```

保存失败时：

```text
只能记到今天哦
日期有点不对
```

这些提示在组件中通过 `toast` 状态展示，并在约 2200ms 后自动消失。

---

## 关闭逻辑

弹窗支持：

```text
点击遮罩关闭
按 Esc 关闭
保存成功后关闭
```

打开弹窗时会锁定页面滚动，关闭后恢复页面滚动。

---

## disabled 状态

当鱼鱼和猫猫都没有任何有效输入时，保存按钮应禁用或不可保存。

判断条件包括：

```text
体重不为空
热量缺口 > 0
运动时长 > 0
```

组件中通过 `hasAnyEffort` 判断是否存在有效努力。

---

## empty 状态

记录弹窗本身没有传统 empty 状态，但如果选择某日期无记录，应显示默认输入值。

---

## error 状态

错误包括：

```text
未来日期
无效日期
无有效输入
```

错误不应打断页面，而应通过 toast 或按钮禁用处理。

---

## 移动端适配

* 弹窗底部贴近移动端；
* 小屏下鱼鱼和猫猫卡片应避免内容溢出；
* 输入字段必须保持紧凑；
* 不应出现横向滚动。

---

# 7. DualMonthlyHeatmaps 成长地图

## 页面位置

首页成长地图区域。

## 功能目标

展示鱼鱼和猫猫在一个月份中的成长状态。

## 展示内容

包含：

```text
月份标题
上个月 / 下个月按钮
本周坚持天数
作战开始日输入
鱼鱼热力图
猫猫热力图
图例
```

`DualMonthlyHeatmaps` 内部维护当前查看月份，并根据每日记录生成鱼鱼和猫猫两张热力图。

---

## 用户操作

### 切换月份

```text
点击 ‹ 查看上个月
点击 › 查看下个月
```

系统响应：

```text
更新 viewMonthDate
重新计算 monthLabel
重新生成鱼鱼/猫猫热力图
```

### 修改作战开始日

用户修改 date input 后，系统调用 `updateHeatmapStartDate` 更新起始日。

---

## 系统行为

系统根据：

```text
dailyRecords
heatmapStartDate
viewMonthDate
fishHeatByDate
catHeatByDate
```

生成月度热力图。

---

## empty 状态

如果当前月份没有记录：

* 热力图显示空格或未完成状态；
* 周标签可根据是否有当月记录决定展示方式。

代码中存在 `hasMonthRecords` 判断。

---

## error 状态

如果开始日格式不合法，使用默认开始日。

`resolveVisibleStartDate` 会校验日期字符串格式，不合法时使用 fallback。

---

## 移动端适配

* 热力图不应横向溢出；
* 图例可以换行；
* 月份切换按钮应可点击；
* date input 不应挤压标题。

---

# 11. HomeResourcesProvider 状态提供器

## 页面位置

包裹首页所有组件。

## 功能目标

提供全局资源状态和操作方法。

## 提供的数据

包括：

```text
宝石库存
金币库存
每日记录
兑换记录
兑换类别
热力图配置
金币规则
视觉规则
成长统计
记录操作方法
兑换操作方法
编辑删除方法
```

`HomeResourcesProvider` 的 context value 中包含钱包、统计数据、每日记录、兑换记录、兑换类别、记录增删改、兑换记录更新删除、热力图起始日更新等奖励和记录相关能力。

---

## 初始化逻辑

组件初始化时创建默认状态，挂载后从本地存储读取真实数据，并写入 React state。

---

## 数据写入逻辑

状态变化通过 `commitHomeState` 更新内存状态，并写入本地存储。

---

## error 状态

如果外部组件不在 Provider 内调用 `useHomeResources`，系统抛出错误。

# 12. 全局交互规范

## 12.1 弹窗

所有弹窗应遵守：

```text
打开时锁定页面滚动
点击遮罩关闭
Esc 关闭
内容过长时弹窗内部滚动
关闭后恢复页面滚动
```

## 12.2 表单

表单应遵守：

```text
字段清晰
单位明确
无效输入不破坏数据
保存前可预览结果
保存成功后给 toast
```

## 12.3 资源展示

统一格式：

```text
💎 +6
💎 5
🪙 +2
🪙 0
```

## 12.4 危险操作

删除类操作：

```text
不直接暴露在主列表
放入编辑流程
弱化样式
必要时二次确认
```

## 12.5 空状态

空状态应温和、简短，避免后台感。

## 12.6 移动端

重点检查：

```text
375px
390px
430px
768px
```

要求：

```text
不横向滚动
不文字重叠
不按钮挤压
不弹窗溢出
不输入框撑爆
```

# 13. 页面交互完成标准

项目页面交互可认为达标，当满足：

1. 首页能进入所有核心功能；
2. 记录弹窗能完成记录、补录和编辑；
