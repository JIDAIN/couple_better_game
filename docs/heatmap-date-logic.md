# 热力图日期逻辑说明

## 1. 起始日是什么

首页的“第一周起始日”现在表示的是**记录起始日**，不是“强制周六”。

系统会把这个日期放到它真实对应的星期位置：

- 周六 -> 第 1 列
- 周日 -> 第 2 列
- 周一 -> 第 3 列
- 周二 -> 第 4 列
- 周三 -> 第 5 列
- 周四 -> 第 6 列
- 周五 -> 第 7 列

对应工具函数在 [components/home/mockHeatmapData.ts](../components/home/mockHeatmapData.ts)：

- `getWeekdayIndexForSatStart(date)`
- `getSatStartWeekStart(date)`
- `formatDateKey(date)`

## 2. 热力图如何落格

热力图网格由 `buildMonthGridByStartDate()` 生成。

处理方式是：

1. 取当前查看月份的第一天和最后一天。
2. 取用户保存的记录起始日。
3. 从“起始日所在周”的周六开始排版。
4. 起始日之前的格子保留空白。
5. 之后的日期按自然日期连续填入。

这样可以保证：

- 起始日不会被错误地塞到周六格。
- 如果起始日是周一，它就会落在周一列。
- 后续日期仍然按真实星期列继续显示。

## 3. 为什么周次仍然是周六到周五

热力图的视觉周次和金币规则是两套东西。

目前金币与打卡统计仍然按“周六开始、周五结束”计算，这部分逻辑保留在 [components/home/settlement-rules.ts](../components/home/settlement-rules.ts) 里。

热力图只是把日期摆到正确的位置上，不改变周计算口径。

## 4. 为什么现在可以设置更早的日期

以前界面会把保存的起始日期往默认值上拉回去，导致早于默认范围的日期无法正常显示。

现在 `DualMonthlyHeatmaps` 只要拿到合法的 `YYYY-MM-DD`，就会直接使用，不再强制改回默认起点。

所以像 `2026-04-24`、`2026-04-25` 这类更早的日期，也可以正常作为热力图起始日保存和回显。

## 5. 数据如何映射到格子

`dailyRecords` 里的每条记录都以 `recordDate` 作为唯一日期键。

热力图生成时会：

- 用 `recordDate` 匹配当天的热力图数据
- 通过 `formatDateKey()` 生成统一的日期键
- 找不到记录时显示空格

所以只要 `dailyRecords` 里有任意日期，热力图都会落到对应的星期格子里。
