# 功能需求文档：双人变美变瘦大作战

## 1. 文档目的

本文档用于说明项目当前阶段需要实现的功能范围、模块边界、用户操作、系统响应、数据变化、异常情况和验收标准。

当前阶段为  **Web MVP** ，核心目标是完成基础闭环：

```text
记录今天 → 获得宝石/金币 → 点亮成长地图 → 查看成长日志 → 兑换奖励
```

---

## 2. 功能模块总览

当前 MVP 包含以下模块：

```text
1. 今日记录模块
2. 奖励结算模块
3. 成长面板模块
4. 成长地图模块
5. 成长日志模块
6. 兑换商店模块
7. 数据持久化模块
```

未来规划模块：

```text
8. 数据导入导出模块
9. 登录与多设备同步模块
10. 设置模块
```

当前不单独拆分：

```text
历史记录模块：合并到成长日志模块
兑换记录模块：合并到兑换商店模块
奖励分类管理模块：合并到兑换商店模块
```

---

# 3. 今日记录模块

## 3.1 功能目标

用户可以记录两个人当天的体重、热量缺口和运动时长。系统根据输入内容计算宝石、金币、成长地图状态和成长日志记录。

## 3.2 入口

* 首页主按钮：记录今天
* 历史补录入口
* 成长日志详情页的编辑入口

## 3.3 用户操作

用户可以填写：

```text
鱼鱼体重
鱼鱼热量缺口
鱼鱼运动时长
猫猫体重
猫猫热量缺口
猫猫运动时长
```

## 3.4 系统行为

系统根据用户输入实时计算：

```text
鱼鱼宝石
猫猫宝石
双人 bonus
金币变化
热力图等级
运动角标
今日奖励预览
```

用户保存后，系统生成或更新当日记录。

## 3.5 数据变化

保存后更新：

```text
dailyRecords
wallet.gems
wallet.coins
fishHeat
catHeat
weekGemTotal
weekCoinTotal
weeklySuccessDays
cumulativeSuccessDays
```

## 3.6 异常情况

| 情况             | 系统处理           |
| ---------------- | ------------------ |
| 体重为空         | 允许保存           |
| 热量缺口为空     | 按 0 处理          |
| 运动时长为空     | 按 0 处理          |
| 输入负数         | 按无效输入处理     |
| 当天已有记录     | 更新已有记录       |
| 补录未来日期     | 禁止保存           |
| 没有任何有效输入 | 禁止保存或提示用户 |

## 3.7 验收标准

* 可以记录当天数据；
* 可以补录过去日期；
* 可以编辑已有记录；
* 保存后首页数据更新；
* 保存后成长地图更新；
* 保存后成长日志出现记录；
* 输入为空或无效时不破坏数据；
* 移动端输入不拥挤、不横向溢出。

# 4. 奖励结算模块

## 4.1 功能目标

根据每日记录自动计算宝石、金币和双人加成，给用户即时正反馈。

## 4.2 奖励类型

```text
💎 宝石：每日即时奖励
🪙 金币：周期性高阶奖励
🔥 双人 bonus：两人共同完成时触发
恢复奖励：前一天运动后，今天继续记录时触发
```

## 4.3 用户操作

用户不需要单独操作。
奖励结算由系统在记录、编辑、补录、删除时自动触发。

## 4.4 系统行为

系统根据规则计算：

```text
热量缺口宝石
运动宝石
恢复奖励
双人 bonus
金币变化
```

## 4.5 数据变化

结算结果影响：

```text
当日记录
钱包宝石
钱包金币
本周统计
成长日志摘要
成长地图状态
```

## 4.6 异常情况

| 情况           | 系统处理               |
| -------------- | ---------------------- |
| 未达到奖励条件 | 显示 0 或不显示该项    |
| 编辑历史记录   | 重新计算该日及相关统计 |
| 删除记录       | 回算钱包和统计         |
| 规则变化       | 后续可考虑全量重算     |

## 4.7 验收标准

* 记录保存后奖励计算正确；
* 编辑记录后奖励重新计算；
* 删除记录后资源同步回算；
* 宝石格式统一为 `💎 +n`；
* 金币格式统一为 `🪙 +n` 或 `🪙 0`；
* 不出现单位和资源表达混乱。

# 5. 成长面板模块

## 5.1 功能目标

在首页展示当前阶段的核心成长状态，让用户快速看到最近成果和可用奖励。

## 5.2 入口

首页默认展示。

## 5.3 展示内容

应展示：

```text
昨日宝石
本周宝石
宝石库存
本周金币
金币库存
连续坚持情况
```

## 5.4 用户操作

用户不需要直接操作该模块。
该模块用于查看状态。

## 5.5 系统行为

系统根据每日记录和钱包状态自动更新展示。

## 5.6 数据变化

该模块只读取状态，不直接修改数据。

## 5.7 异常情况

| 情况       | 系统处理                       |
| ---------- | ------------------------------ |
| 无记录     | 显示 0 或温柔空状态            |
| 钱包为空   | 显示 `💎 0`/`🪙 0`         |
| 数据加载中 | 使用稳定默认状态，避免页面闪烁 |

## 5.8 验收标准

* 首页能看到当前资源；
* 资源数字清晰；
* 资源格式统一；
* 无数据时不报错；
* 移动端展示不拥挤。

---

# 6. 成长地图模块

## 6.1 功能目标

通过热力图展示两个人每天的完成程度，让用户看到坚持轨迹。

## 6.2 入口

首页成长地图区域。

## 6.3 用户操作

用户可以：

```text
查看当前月份成长地图
切换月份
调整作战开始日
查看鱼鱼和猫猫各自热力图
```

## 6.4 系统行为

系统根据每日记录生成热力图：

```text
不同颜色表示热量缺口完成程度
运动角标表示运动情况
鱼鱼和猫猫分别展示
```

## 6.5 数据变化

用户调整作战开始日时更新：

```text
heatmapStartDate
```

每日记录变化时更新：

```text
fishHeat
catHeat
```

## 6.6 异常情况

| 情况           | 系统处理       |
| -------------- | -------------- |
| 某日无记录     | 显示未完成     |
| 当前月无记录   | 显示空地图     |
| 起始日无效     | 使用默认起始日 |
| 未来月份无数据 | 正常显示空状态 |

## 6.7 验收标准

* 鱼鱼和猫猫各自有热力图；
* 热力图状态颜色清晰；
* 运动角标显示正常；
* 图例不重叠；
* 月份切换正常；
* 小屏无横向滚动。

# 7. 成长日志模块

## 7.1 功能目标

成长日志用于查看和维护每日记录。
它承担历史每日记录的查看、详情展示、编辑和删除。

## 7.2 入口

* 首页入口：成长日志
* 每条日志的详情按钮
* 详情页的编辑按钮

## 7.3 用户操作

用户可以：

```text
打开成长日志
切换月份
查看每日摘要
查看某一天详情
编辑某一天记录
删除某一天记录
```

## 7.4 系统行为

成长日志列表展示摘要：

```text
日期
当天宝石变化
当天金币变化
详情入口
```

详情页展示：

```text
当天总奖励
鱼鱼记录
猫猫记录
双人 bonus
金币变化
编辑入口
```

编辑后，系统重新计算当天奖励和相关统计。

## 7.5 数据变化

编辑或删除后更新：

```text
dailyRecords
wallet
fishHeat
catHeat
weekGemTotal
weekCoinTotal
weeklySuccessDays
cumulativeSuccessDays
```

## 7.6 异常情况

| 情况           | 系统处理            |
| -------------- | ------------------- |
| 当前月份无记录 | 显示空状态          |
| 输入无效       | 阻止保存或按 0 处理 |
| 删除记录       | 二次确认            |
| 删除后无记录   | 显示空状态          |
| 日期不可编辑   | 保持记录日期不变    |

## 7.7 验收标准

* 可以按月份查看成长日志；
* 列表只展示摘要；
* 点击详情可以查看当天完整记录；
* 可以从详情进入编辑；
* 编辑后奖励和热力图同步更新；
* 删除后记录消失并回算数据；
* 小屏无横向滚动；
* 详情页不堆规则说明。

# 8. 兑换商店模块

## 8.1 功能目标

用户可以使用宝石和金币兑换现实奖励，将坚持转化为生活中的正反馈。

兑换商店模块包含三个子功能：

```text
奖励兑换
兑换记录
奖励分类管理
```

---

## 8.2 奖励兑换

### 功能目标

用户可以查看可兑换奖励，并使用宝石或金币进行兑换。

### 入口

首页入口：兑换商店。

### 用户操作

用户可以：

```text
查看宝石奖励
查看金币奖励
选择奖励
填写备注
选择时间
确认兑换
```

### 系统行为

系统判断资源是否足够：

```text
足够：允许兑换
不足：禁用兑换或显示差一点
```

兑换成功后生成兑换记录并扣除资源。

### 数据变化

更新：

```text
wallet.gems
wallet.coins
exchangeRecords
```

### 异常情况

| 情况     | 系统处理     |
| -------- | ------------ |
| 宝石不足 | 禁止兑换     |
| 金币不足 | 禁止兑换     |
| 备注为空 | 允许兑换     |
| 时间为空 | 使用当前时间 |
| 兑换失败 | 不扣资源     |

### 验收标准

* 资源足够时可兑换；
* 资源不足时不可兑换；
* 兑换后钱包正确扣减；
* 兑换后生成记录；
* 价格格式统一为 `💎 5` / `🪙 4`。

---

## 8.3 兑换记录

### 功能目标

用户可以查看和维护自己的兑换历史。

### 入口

兑换商店内的已兑换记录区域和查看记录入口。

### 用户操作

用户可以：

```text
查看最近兑换记录
查看全部兑换记录
编辑兑换备注
编辑兑换时间
删除兑换记录
```

### 系统行为

系统展示兑换记录，并支持编辑。
删除操作放在编辑流程中，不直接暴露在列表项上。

### 数据变化

更新：

```text
exchangeRecords
wallet.gems
wallet.coins
```

如果删除兑换记录，需要同步回算对应资源。

### 异常情况

| 情况         | 系统处理   |
| ------------ | ---------- |
| 无兑换记录   | 显示空状态 |
| 编辑为空备注 | 允许保存   |
| 删除记录     | 二次确认   |
| 删除后无记录 | 显示空状态 |

### 验收标准

* 兑换记录可查看；
* 最近记录可在商店内展示；
* 全部记录可在弹窗中查看；
* 记录可编辑；
* 记录可删除；
* 删除后资源正确回算；
* 列表项不直接显示删除按钮。

---

### 功能目标

用户可以维护兑换商店中的奖励类别。

### 系统行为

### 数据变化

更新：

```text
exchangeCategories
```

### 异常情况

| 情况     | 系统处理               |
| -------- | ---------------------- |
| 名称为空 | 使用默认名称或阻止保存 |
| 图标为空 | 使用默认图标           |
| 价格无效 | 使用默认价格或阻止保存 |

# 9. 数据持久化模块

## 9.1 功能目标

当前 MVP 使用本地存储保存用户数据，保证刷新页面后数据不丢失。

## 9.2 用户操作

用户无需手动操作。

## 9.3 系统行为

系统应：

```text
初始化默认状态
读取本地数据
归一化旧数据
写入最新状态
在状态变化后保存
```

## 9.4 数据变化

本地保存：

```text
wallet
dailyRecords
exchangeRecords
exchangeCategories
heatmapStartDate
coinRules
visualRules
```

## 9.5 异常情况

| 情况         | 系统处理         |
| ------------ | ---------------- |
| 本地无数据   | 创建默认状态     |
| 本地数据损坏 | 使用默认状态兜底 |
| 旧数据格式   | 尝试归一化       |
| 写入失败     | 保持当前内存状态 |

## 9.6 验收标准

* 刷新后数据不丢失；
* 本地无数据时正常初始化；
* 本地数据异常时页面不崩溃；
* 状态变化后能保存。

# 15. 模块边界总结

```text
今日记录模块：创建每日记录
奖励结算模块：计算宝石金币
成长面板模块：首页状态展示
成长地图模块：可视化坚持情况
成长日志模块：查看、编辑、删除每日记录
兑换商店模块：兑换奖励、管理兑换记录、管理奖励类别
数据持久化模块：本地保存和恢复
未来模块：导入导出、登录同步、设置
```

这样整理后，模块边界更清晰：

* “历史记录”不单独存在，属于成长日志。
* “兑换记录”不单独作为一级模块，属于兑换商店。
* “奖励分类管理”不单独作为一级模块，属于兑换商店。
